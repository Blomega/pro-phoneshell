KnowU-Bench finds proactive failure is a calibration problem, not a navigation one: Claude intervenes wrongly 60% of the time it fails

KnowU-Bench (arXiv:2604.08455, Zhejiang University, Apple and Tencent, submitted 9 April 2026) scores mobile agents on three axes beyond whether a task got done: interactive, proactive, personalized. Claude Sonnet 4.6 leads the field on overall success at 60.4%, but the paper's own failure breakdown shows that when Claude fails a proactive task, 60% of those failures are the agent intervening when it should have stayed quiet, against 15% that are plain GUI mistakes. phoneshell's Check list has no field for why a task failed, only a device-state read of whether it did.

"KnowU-Bench: Towards Interactive, Proactive, and Personalized Mobile Agent Evaluation" (arXiv:2604.08455v1, 16 authors including Tongbo Chen, Zhengxi Lu and Yongliang Shen, affiliated with Zhejiang University, Apple and Tencent) argues that task completion alone hides three separate skills a deployed assistant needs. Interactive tasks test whether an agent asks for missing information instead of guessing, scored through an Interaction Efficiency metric that rewards resolving a task in fewer clarifying questions. Personalized tasks hide a user's preferences in behavioral logs the agent can read but never see labeled as a profile, so the agent has to infer what the user wants from the pattern of past choices rather than from a stated rule. Proactive tasks go further still: "proactive tasks omit explicit instructions entirely," and the agent must decide for itself whether to act directly, propose an action and wait for confirmation, or do nothing at all.

192 tasks, four personas, and an app count the paper does not reconcile

The benchmark splits into "42 general tasks, 86 personalized tasks, and 64 proactive tasks," 192 by our own addition since the paper does not total them in one place. Four fixed personas carry the personalization signal: Developer, Grandma, Student, Researcher, each with its own behavioral history. The app count is less settled: Section 3.1 states "23 applications in total," while the paper's own Table 5 lists 17. The paper does not reconcile the two figures anywhere in its text, which is worth flagging exactly as stated rather than picking one number to repeat as fact.

What Claude's own failures are made of

Overall success rate flattens three different skills into one number, and KnowU-Bench's own failure-cause breakdown for the leading model shows why that flattening hides the more useful fact. When Claude Sonnet 4.6 fails a personalized task, the paper categorizes each failure, and "Clarify" failures, the agent should have asked a question about the user's preference and did not, account for 66.7% of them. "Partial" failures, where the agent gets part of the preference right but not all of it, are 27.1%. Plain GUI execution mistakes are only 4.2%, and getting the preference itself wrong despite having the right information is 2.1%. On proactive tasks the same pattern repeats in a different shape: "Intervention" failures, acting when the agent should have stayed silent or only confirmed, make up 60.0% of Claude's proactive failures. "Passive" failures, staying silent when action was called for, are 20.0%. GUI execution errors are 15.0%, and outright wrongly rejecting a valid confirmation is 5.0%. The paper states the conclusion these numbers point to directly: "proactive failure is primarily a calibration problem rather than an execution problem."

What it means for reading a mobile agent's success rate

A single success-rate number cannot tell you whether a model fails because it cannot find the right button or because it does not know whether it should press one. KnowU-Bench's contribution is making that distinction visible inside a benchmark score rather than leaving it to a reader's guess, and its own summary states the finding as the paper's actual thesis: "existing models can often navigate the interface, but they still struggle to decide what should be done for which user and when it should be done." For anyone choosing a model to run unattended on a personal device, that is a materially different thing to optimize for than raw GUI accuracy, and a leaderboard built only from task completion will not surface it.

phoneshell's own Check list grades a task from device state, pass or fail, with no further taxonomy at all: the house thesis is that a screenshot is worth 100 points or zero depending on whether the answer lives in the accessibility tree, which is a claim about information availability, not about why an agent chose the action it chose. KnowU-Bench's failure categories, Clarify, Partial, Intervention, Passive, Rejection, describe decisions a device-state check cannot distinguish from each other: two failed proactive tasks that both end in the wrong Siri Shortcut running look identical to a pass/fail grader even when one was an agent that acted too eagerly and the other was an agent that acted on the wrong information entirely.

What would prove this wrong

We claim KnowU-Bench's Table 2 reports an overall success rate of 60.4% for Claude Sonnet 4.6 against 29.2% for Qwen3-VL-32B, and that its Section 5 failure analysis attributes 66.7% of Claude's personalized-task failures to missed clarification and 60.0% of its proactive-task failures to wrongful intervention, with the paper's own sentence that this is "primarily a calibration problem rather than an execution problem," all checkable against the cited arXiv v1 HTML. We also note the paper's own unreconciled app count (23 in Section 3.1, 17 in Table 5), checkable the same way. This should be revisited if a later revision resolves that count, or if any model KnowU-Bench evaluates clears 80% overall success without a corresponding drop in Intervention-type failures specifically, by 30 June 2027.
