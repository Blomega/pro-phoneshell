Microsoft's HCU scores 66.08 without its screenshot channel and 65.59 with it

Hybrid Computer Use (arXiv:2610.41432, Microsoft Research, submitted 30 October 2026) gives an agent three channels: code, the accessibility tree (AX) and GUI screenshots with pixel input. In its ablation with GPT-5.4 on 361 OSWorld 1.0 tasks, the full interface scores 65.59%. Take the GUI channel away and the score is 66.08%. Take the AX channel away and it is 62.79%. Each figure is a mean of three runs.

The paper is by Haoqing Wang, Xiaoyi Zhang, Sicheng Fan, Zhexin Zhang, Xinjie Zhang, Jiahao Li, Bin Li and Yan Lu, of Microsoft Research with Fudan and Tsinghua. HCU ships as an MIT-licensed MCP server for Linux, macOS and Windows. Its headline is OSWorld 2.0: 72.37% Partial with GPT-6 Astra and 35.19% Binary with Claude Opus 5, the highest full-set scores among the systems it tabulates. The ablation sits behind that headline, in Table 2 and Appendix C.1, and it speaks directly to the question this site keeps asking: what a screenshot buys once the tree is available.

The authors read the table the same way. Their words: "removing GUI leaves Score within run-to-run variation while increasing Steps by 12.45%." Appendix C.1 gives the runs. Full HCU beats the no-GUI arm by 0.52 and 0.95 points in runs 1 and 2 and loses by 2.97 in run 3; "the contrast with HCU w/o GUI changes sign across runs." The AX contrast does not: HCU leads the no-AX arm by 2.40 to 3.35 points in every run, and the mean gap is 2.79.

What screenshots buy here is steps. With the GUI channel the agent takes 28.60 steps per task, without it 32.16. They cost almost nothing in this design, because the model decides when to look: input tokens go from 0.909M to 0.941M per task (3.4% more) and cost from $2.45 to $2.52 (2.8% more). Against the baseline the saving is large on every axis. CUA Driver, which also offers element-addressed actions, uses 40.74 steps, 2.181M input tokens and $5.65 per task for a score of 62.30%.

The ablated model is the one that uses screenshots least

Section 4.4 compares four models on the same interface, each in its vendor's own agent CLI. Of their AX and GUI calls, GPT-5.4 sends 80% to AX, Grok 4.7 sends 68% and Gemini 3.8 Flash 51%. Then: "Claude instead uses GUI for 94% of these calls," which leaves 6% for AX. All four score higher with HCU than with CUA Driver: by 3.29 points for GPT, 6.81 for Grok, 12.90 for Gemini and 2.94 for Claude Opus 5.5.

The channel ablation was run with GPT-5.4 only. So the 66.08 against 65.59 result describes a model that already routes four calls in five through the tree. Whether a no-GUI arm would hurt the model that routes 94% through pixels is not in the paper. Claude's 2.94-point gain also came with steps down 1% and time up 6%, and it is the only one of the four whose step count did not fall, which fits a model that kept working mostly the way it did before.

Three of the models mix channels inside a task. On 29% to 31% of the tasks where GPT, Gemini or Grok used GUI at all, every GUI call was a screenshot and every action went through AX. That is a look-with-pixels, act-through-the-tree split, chosen by the model.

The guards are what make mixing safe. Before an AX action the target guard resolves the ref against live state and rejects a missing, ambiguous or replaced element as stale_ref. Before a GUI coordinate action the layout guard compares the live window layout with the one registered by the last screenshot and on mismatch blocks input with gui_frame_stale. Table 11 counts how often staleness fired: 88 stale-category errors in 10,783 AX and GUI calls, 0.82%, across 1,083 task-runs. All AX and GUI errors together were 638 of 10,783, 5.9%. The project page gives a batch limit of up to 64 actions per call.

What it means for the tree-versus-pixels decision

Our house result is the forced version of this experiment. In 120 paired runs on a physical iPhone 17 Pro Max, attaching the screenshot changed nothing when the answer was in the accessibility tree and added about 35% to per-step cost; when the answer existed only as pixels, success was 100% with the image and 0% without it. HCU's number is the optional version on desktop. Let the model ask for the image only when it wants one, and the image costs 2.8% per task with no measurable score effect for a tree-preferring model. The two agree on direction. The size of the tax depends on who decides when to look.

OSWorld 1.0 is also not a pixel-only test set. The paper reports no split of the 361 tasks by whether the tree carries the answer, so 66.08 without GUI cannot be read as "screenshots are unnecessary." It says these tasks, for this model, rarely needed them.

One caution on the numbers that travel. The project page leads with 70.13% on OSWorld 1.0 at 59.1% lower cost than CUA Driver. That is the released version, which Appendix A says was refined after the experiments: "we refined the interface and skill into the released version." The evaluated version behind the ablations scores 65.77% on the same 360 tasks. The run count for the released figure is not reported.

phoneshell guards the same seam differently. It does not keep element handles across a re-render; a comment in phoneshell/actions.py gives the reason: "handles go stale the instant the tree re-renders." It taps a coordinate from the snapshot the model reasoned about, and before the tap phoneshell/agent/verify.py crops the element's rect from the current frame and checks that the claimed label is what the pixels show. HCU re-resolves the reference; we re-read the pixels. HCU's 88 in 10,783 is the first published rate we have seen for how often a live-state guard fires, and we have not measured ours.

What would prove this wrong

We claim that arXiv:2610.41432v1 shows no score loss from removing HCU's screenshot channel for GPT-5.4 on OSWorld 1.0, and that it does not test the model most dependent on that channel. Our prediction: if a no-GUI ablation for Claude Opus 5.5 (or its successor in Claude Code) on the same task set is published by 30 June 2027 with at least three runs, the full interface will beat the no-GUI arm in every run. A result where the no-GUI arm matches or beats full HCU for a model that sends over 90% of its desktop calls to GUI would show the screenshot channel is dispensable more broadly than this paper establishes.
