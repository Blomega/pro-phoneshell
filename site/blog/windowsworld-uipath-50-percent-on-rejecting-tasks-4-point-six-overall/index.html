WindowsWorld's infeasible-task score rewards giving up: UiPath scores 50% on it while passing 4.64% of tasks overall

WindowsWorld (arXiv:2604.27776, Harbin Institute of Technology, Shenzhen, submitted 30 April 2026) adds a fourth difficulty tier, L4, made entirely of tasks that cannot be completed: invalid URLs, missing files, instructions that need authentication the agent does not have. An agent earns L4 credit by correctly calling a failure action instead of attempting the task. In the paper's own Table 2, UiPath w/ Gemini-3-flash-preview scores 50.00% on L4, the highest score in the entire table, while its overall S_final average across all four tiers is 4.64%, the second-lowest score in the table.

WindowsWorld's stated motivation is that prior GUI-agent benchmarks "mainly focus on isolated and single-application tasks," overlooking workflows that span multiple professional applications. Its six authors (Jinchao Li, Yunxin Li, Chenrui Zhao, Zhenran Xu, Baotian Hu, Min Zhang) built 181 tasks across 17 Windows desktop applications, generated through a multi-agent pipeline steered by 16 occupations and refined by human review, with 77.9% of tasks requiring two or more applications. The best model overall, Gemini-3-flash-preview with a hybrid screenshot-plus-accessibility-tree input, reaches a 20.44% S_final average, matching the paper's own framing that "the best agents only achieve a 20% success rate."

L4 counts a refusal as correct, whatever caused it

Section 3.2 defines L4 tasks as "intentionally unachievable due to factors such as invalid URLs, missing files, or required account authentication," and Section 3.5 scores them under the Final Check Score, which "assesses the correctness of the terminal state, including the agent's ability to correctly reject infeasible instructions." The action space includes a FAIL() primitive alongside DONE(); calling it on an L4 task is counted as a correct terminal state. Nothing in that scoring rule distinguishes an agent that investigated the task and determined it was impossible from an agent that gives up constantly and happened to give up on the right ones too.

Table 2's own numbers show the gap that rule leaves open. UiPath w/ Gemini-3-flash-preview, the one commercial RPA-style agent in the table, scores 0.00% on L2 and L3, 3.03% on L1, and 50.00% on L4, an S_final average of 4.64%. GPT-5.2 under Set-of-Marks prompting shows the same shape: 0.00% on L1 through L3, 25.00% on L4, an average of 0.55%. Both scored far better on the tier built from tasks that cannot be done than on the tiers built from tasks that can.

One action, two different reasons to take it

The mechanism is a single shared exit: calling FAIL() scores the same whether it follows genuine diagnosis (the agent checked the URL, found it broken, and correctly reported the task cannot be done) or indiscriminate refusal (the agent calls FAIL() on most things it is unsure how to start, and some of those happen to be the L4 tasks). WindowsWorld's own Table 2 cannot distinguish the two paths from the score alone, because L4's acceptance criterion, per Section 3.5, is the correctness of the terminal state, not the reasoning that produced it.

What it means for reading an infeasibility score

An "ability to reject unachievable goals" score is only informative alongside the completion rate on achievable ones; read alone, it rewards two opposite behaviors with one number. WindowsWorld's conclusion correctly names "the ability to reliably report task failure" as "a significant open challenge," but Table 2 as published does not let a reader separate a model that is good at this specific judgment from a model that is simply bad at everything, including starting. A benchmark can fix this without dropping the L4 idea: score L4 against a false-positive rate measured on the L1-L3 tasks the same run attempted, so an agent that quits constantly is penalized for the quitting on the tiers where quitting is wrong, not rewarded for the coincidence of quitting on the tiers where it happens to be right.

Separately, the paper's own Section 4.2 text states that Gemini-3-flash-preview's "S_final plummets from 35.90% (L1) to 16.67% (L3)." Table 2 lists L3 for that row as 14.00%, not 16.67%; the 16.67% figure is the row's L4 score. The two numbers are close enough that the error does not change the paper's qualitative claim, a declining trend across tiers, but it is checkable directly against the table the sentence is describing, and a reader citing the prose instead of the table would cite the wrong tier.

What would prove this wrong

We claim Table 2 of arXiv:2604.27776v1 reports UiPath w/ Gemini-3-flash-preview scoring L1 3.03%, L2 0.00%, L3 0.00%, L4 50.00%, S_final Avg 4.64%, and GPT-5.2 under Set-of-Marks prompting scoring 0.00% on L1-L3, 25.00% on L4, and an average of 0.55%, both checkable directly against the cited arXiv v1 HTML. This should be revisited if a later revision of the paper adds a false-positive-adjusted L4 metric that still shows UiPath or a similarly low-scoring agent leading on infeasibility rejection, or if the authors clarify that the 16.67% figure in Section 4.2 was intentional rather than a tier mislabel, by 30 June 2027.
