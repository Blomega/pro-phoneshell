MemU-Bench's best model reaches 16.4% SPL with no memory aid; the one GUI specialist tested falls to 3.4%

MemU-Bench (arXiv:2611.00191, Zhejiang University and Ant Group, submitted 30 October 2026) grounds 118 tasks in 29 real user trajectories of 100 to 800 steps each, where the instruction leaves out details the user has already forgotten and the agent has to reconstruct them from raw interaction history. Without any memory aid, the best frontier model, Gemini-3.1-Pro, reaches 16.4% success-weighted path length (SPL) on the full set, and MAI-UI-8B, the one end-to-end GUI-specialist model tested, falls to 3.4%. Every model in the paper runs exactly once, at temperature zero, on an Android Virtual Device. phoneshell's own leaderboard runs each task as a pre-registered, paired comparison and grades every one from a physical iPhone's device state, never from a replayed log.

"MemU-Bench: Benchmarking GUI Agents on Long-Horizon User Interactions" (arXiv:2611.00191v1, 15 authors including Yizhou Liu, Zhengxi Lu and Yongliang Shen, Zhejiang University and Ant Group) targets a gap the authors state plainly: real instructions are "vague and history-dependent," because "users omit the exact details of their past operations since they no longer remember them." The benchmark's 118 tasks sit on top of 29 long-horizon trajectories covering more than 30 applications, with "100 to 800 steps per trajectory" and "up to 179 application switches within a single trajectory." The paper splits tasks by how much history an agent has to search: 71 Level-1 tasks have fewer than 400 screenshots behind them, and 47 Level-2 tasks have more than 700. Screenshots are captured "at 0.3-second intervals," which is how a 179-switch trajectory turns into hundreds of individual frames an agent's memory system has to compress.

Three phases, and a second score that is lower than the first

Each MemU-Bench task runs in three phases: build a memory bank from the raw interaction stream, retrieve the key facts the vague instruction needs, then execute online against the live app. Outcomes are "verified against serialized application databases" where possible, and against a vision-language judge "for a minority of tasks where the database is inaccessible." The paper reports two numbers side by side: success rate (SR), whether the task was completed at all, and success-weighted path length (SPL), which discounts a success by how many extra steps it took to get there. SPL is always the lower of the two, and it is the number the paper's own abstract leads with: "the best-performing Gemini-3.1-Pro achieves an SPL of only 16.4%, and end-to-end GUI agents fall below 5%."

AppMem is the paper's own proposed system, and it is doing real work in that chart: it roughly triples or quadruples every model's vanilla score. But the comparison the abstract chose to lead with is the one without it, because that is the condition that answers the question the benchmark was built to ask: can today's agents handle a vague instruction unaided. Four general-purpose frontier models land in a tight 9.7% to 16.4% band with no history support at all. MAI-UI-8B, the paper's lone representative of a different agent category, specialist models trained end-to-end for GUI control rather than prompted as a general assistant, sits at under a quarter of the weakest frontier model's score.

What AppMem removes, and what breaks when it is removed

The paper isolates the piece of AppMem doing the work with a direct ablation. For Qwen3.5-397B-A17B, the full AppMem pipeline scores 47.1% SPL; strip out its Information Filtering step, which the paper describes as narrowing hundreds of retrieved screenshots down to the ones relevant to the current instruction, and the score drops to 41.8%. That is a 5.3-point fall from removing one stage of a four-stage pipeline, on a benchmark where the full pipeline itself recovers only about half of what a clean, fully-specified instruction would be expected to score.

What it means for reading a memory claim

MemU-Bench tests a real and underserved failure mode: an agent that can tap every button correctly but still fails because it never knew which button mattered, since that fact lived three hundred steps ago in a session it was never shown. The authors are explicit that this is their point, that the benchmark is built to separate memory failure from execution failure. Read next to phoneshell's own house finding, that a screenshot is worth 100 points or zero and never in between depending on whether the answer exists in the accessibility tree, MemU-Bench describes a different axis entirely: the information might sit in neither the screen nor the tree, only in a log the agent has to summarize correctly. A benchmark score on MemU-Bench says nothing about an agent's ability to act on a screen it can already see; it says something about an agent's ability to decide what it is looking for before it starts looking.

The paper's own methodology section is a caution for anyone citing these percentages as a ceiling or a floor: every model gets one run, at temperature zero, because of trajectory cost, and the online execution environment is an Android Virtual Device, not a physical phone. A single untested run on an emulator is not nothing, but it is also not the same claim as a number that has been run twice and compared statistically, and it says nothing at all about whether the same memory system would behave the same way against the timing, animation, and permission-dialog variance of a real device.

What would prove this wrong

We claim MemU-Bench's abstract and Table 2 report a vanilla SPL of 16.4% for Gemini-3.1-Pro and 3.4% for MAI-UI-8B, rising to 54.5% and 16.2% respectively with AppMem, and that Table 3's ablation shows Qwen3.5-397B-A17B's SPL falling from 47.1% to 41.8% when Information Filtering is removed, all checkable directly against the cited arXiv v1 HTML. This should be revisited if a later revision of the paper adds a physical-device run, or if a model specifically trained for long-horizon memory retrieval clears 50% vanilla SPL on this benchmark without AppMem-style assistance, by 30 June 2027.
